# Phase 1.5 — Structured bindings & `if constexpr`

Both features are C++17. The default Qt5 build still compiles at C++11, so they
must be **guarded** rather than used unconditionally in shared headers/sources.

## `if constexpr` — use `TL_IF_CONSTEXPR`

`src/tl/tl/tlCxxFeatures.h` provides `TL_IF_CONSTEXPR`, which expands to
`if constexpr` on C++17+ and to a plain `if` on C++11/14. This lets
template-heavy code adopt compile-time dispatch incrementally:

```cpp
#include "tlCxxFeatures.h"

template <class T>
std::string format_coord (const T &c)
{
  TL_IF_CONSTEXPR (std::is_floating_point<T>::value) {
    return tl::to_string (double (c));
  } else {
    return tl::to_string (long (c));
  }
}
```

- On C++17+ the unused branch is *discarded*, so this can replace
  `std::enable_if` / SFINAE overload sets for compile-time dispatch and yields
  much better error messages.
- On C++11 it is an ordinary `if`, identical to the current behaviour, so
  nothing regresses **provided both branches are well-formed for every `T`**.
- If a branch is only valid for some `T` (the real SFINAE-replacement case),
  keep a C++11 fallback (tag dispatch or overloads) and gate the
  `if constexpr` form behind `TL_CXX17`.

### Candidate sites
- Coordinate / transform templates in `db` that branch on integer vs floating
  coordinate types.
- `tlVariant` numeric coercion helpers that today dispatch via overloads.
- Serialization templates that branch on `is_trivially_copyable`.

## Structured bindings — guard with `TL_CXX17`

Structured bindings have no macro shim (there is no C++11 spelling), so they are
introduced only under a guard, keeping the classic loop as the fallback:

```cpp
#if TL_CXX17
  for (auto &[name, cell] : layout.cells_by_name ()) {
    use (name, cell);
  }
#else
  for (auto i = layout.cells_by_name ().begin (); i != layout.cells_by_name ().end (); ++i) {
    use (i->first, i->second);
  }
#endif
```

Because this duplicates the loop body, prefer it only where it materially
improves readability (deeply nested `i->second.first` style access) — e.g. the
map iteration in `dbLayout.cc`. For the common case, the Phase 3.1 range-based
`for (const auto &pair : m)` rewrite (valid in C++11) already removes the
iterator boilerplate without needing a guard.

## Action taken
- Added `TL_IF_CONSTEXPR` to `tlCxxFeatures.h` (verified at C++11/17/20).
- Documented the guarded structured-binding pattern. Wholesale loop rewrites are
  handled in Phase 3.1 with C++11-safe range-based `for`.
