# Phase 5.2 — `std::mdspan` for grid operations

`std::mdspan` (C++23) is a non-owning, multi-dimensional view over a contiguous
buffer. It replaces the manual `row * width + col` index arithmetic that grid /
raster code does by hand, without copying or owning the data.

## Where it applies in KLayout

- **DRC rasterization.** Width/height grids of cells/pixels are stored as flat
  arrays and indexed manually; an `mdspan<T, dextents<size_t, 2>>` makes the 2D
  structure explicit and bounds-describable.
- **Image processing layers** (`tlPixelBuffer` and consumers): pixel rows over a
  flat RGBA buffer.
- Any `(ptr, width, height)` triple passed around as separate parameters — the
  Phase 4.2 `tl::span` handles the 1D case; `tl::mdspan` handles 2D/3D.

## Availability / guard

Exposed as `tl::mdspan` / `tl::extents` / `tl::dextents` via `tlCxxFeatures.h`
behind `TL_HAS_MDSPAN`. Note this is genuinely forward-looking: `<mdspan>`
landed in GCC 14 / Clang 17 / MSVC 19.39, so on the toolchains that build the
default releases today `TL_HAS_MDSPAN` is 0 and the alias is simply absent.

```cpp
#if TL_HAS_MDSPAN
  tl::mdspan<uint8_t, tl::dextents<size_t, 2>> grid (buffer, rows, cols);
  for (size_t r = 0; r < grid.extent (0); ++r) {
    for (size_t c = 0; c < grid.extent (1); ++c) {
      grid[r, c] = compute (r, c);   //  multidim subscript (C++23)
    }
  }
#else
  for (size_t r = 0; r < rows; ++r) {
    for (size_t c = 0; c < cols; ++c) {
      buffer[r * cols + c] = compute (r, c);
    }
  }
#endif
```

## Action taken
Added the guarded `tl::mdspan` family alias to `tlCxxFeatures.h`. No hot-path
rasterization code is converted yet: that should be done together with a
benchmark (see `doc/modernization/benchmarks/`) once a `<mdspan>`-capable
toolchain is part of the standard build matrix, since the abstraction must be
confirmed zero-cost on the DRC inner loops before adoption.
